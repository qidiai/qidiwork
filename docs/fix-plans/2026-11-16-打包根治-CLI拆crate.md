# 方案：根治「安装包误带 CLI 二进制」——CLI 拆独立 crate

**日期**：2026-11-16
**触发**：codely-core 审计阻断——安装包出现未声明的 `bid_export.exe`，且 `"externalBin": []` 也关不掉。
**目标**：让 GUI 安装包**只含应用本体 + 内核 + 模板**；CLI 成为独立可分发物；两者模板解析都不再靠"猜目录"。

---

## 1. 事实基线（已实测）

| 事实 | 证据 |
|---|---|
| 打包会带上 `bid_export.exe`（1.9 MB） | `target/release/nsis/x64/installer.nsi:646-647` |
| 干净重建（删 `nsis/`+`bundle/`）两次均复现 | 2026-11-16 21:14 / 21:27 两次构建 |
| 显式 `"externalBin": []` 无效 | 同上，21:27 构建仍含该文件 |
| 其余 5 个 bin 未被打包（bid_import/pages/project/smoke/gen_bid_template） | `grep` NSI 仅命中 bid_export |
| `qidiwork.exe`（132 MB 内核）是**有意**随包 | `src/process/mod.rs:38-43` 按 `<resource_dir>/qidiwork.exe` spawn |
| CLI 模板默认路径是开发态路径 | `paths::resolve_from` 的 dev 回退用 `CARGO_MANIFEST_DIR`；装到 Program Files 后该路径不存在 |

**结论**：同包多 bin 时，Tauri 的"主二进制/外部二进制"判定不可控且无配置出口；把 CLI 留在 GUI 包里，无论修不修模板路径，都是"未声明行为"。根治只能让 GUI 包**只剩一个 bin**。

---

## 2. 候选方案

| 方案 | 做法 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| **A 拆 crate** | 新建 workspace 成员 `gui/cli`（crate `qidiwork-cli`），把 6 个 bin 迁过去，依赖 `qidiwork-gui` 库 | GUI 包只剩主 bin，问题根除；CLI 可单独发版；职责清晰 | 一次迁移成本；文档命令要改 | **推荐** |
| B feature gate | 6 个 bin 加 `[[bin]] required-features=["cli"]`，cli 不进 default | 不动目录结构 | 开发/CI 每条命令都要 `--features cli`；Tauri 构建是否传 `--no-default-features` 不可控，仍有被打包风险 | 不推荐 |
| C 正式随包 | 承认 CLI 是产品一部分，修好安装态模板解析 | 少改动，用户可在安装目录直接跑 CLI | 仍然只有 `bid_export` 一个被"随机"带上，其余 5 个没有；行为依旧不可解释 | 仅作 A 的过渡 |
| D 构建后剔除 | `beforeBundleCommand` 删除 `target/release/bid_export.exe` | 一行脚本 | 依赖 Tauri 钩子时序，脆弱；治标 | 不采用 |

---

## 3. 方案 A 施工设计

### 3.1 目标结构

```
gui/
  src-tauri/            # crate qidiwork-gui（库 + 唯一 bin: qidiwork-gui）
    src/main.rs
    src/office/bid/...  # 引擎与全部单测（不动）
  cli/                  # 新 crate qidiwork-cli（6 个 bin）
    Cargo.toml          # [dependencies] qidiwork-gui = { path = "../src-tauri" }
    src/bin/{bid_export,bid_import,bid_pages,bid_project,bid_smoke,gen_bid_template}.rs
```

`gui/src-tauri/Cargo.toml`：
```toml
[workspace]
members = [".", "cli"]
```

### 3.2 迁移步骤

1. 新建 `gui/cli/Cargo.toml`（`name = "qidiwork-cli"`，`edition 2024`，依赖 `qidiwork-gui` path + `serde`/`serde_json`；**不引新依赖**）。
2. `git mv` 6 个文件：`src-tauri/src/bin/*.rs` → `cli/src/bin/`。
3. 修正 import：bin 里若有 `use qidiwork_gui::...` 保持；若用到 crate 内私有项，改为 `pub` 导出（预期只有 `paths::probe_resolve` 已 pub）。
4. **模板解析改造**（两处，重要）：
   - `paths` 增加 `pub fn resolve_for_exe(style_id: &str) -> Result<PathBuf, String>`：
     先 `std::env::current_exe()?.parent()/templates/<id>.docx`（安装态/同目录），再 `CARGO_MANIFEST_DIR/resources/templates`（开发态），命中即返回；返回时同时给出 `source`（`resource`/`dev`）。
   - CLI 默认模板改用 `resolve_for_exe`；`--template` 显式指定仍然优先。
   - GUI 内 `resolve_template_path(app, …)` 不变（有 AppHandle 时 resource_dir 更准）。
5. `gen_bid_template` 默认输出目录改为"exe 同级 resources/templates"不可写时回退 `CARGO_MANIFEST_DIR/resources/templates`；无参数行为保持"开发态可用"。
6. 删除 `src-tauri/Cargo.toml` 里的 `[[bin]]`/`default-run` 之外的 CLI 相关残留（`[[bin]]` 保留主 bin 声明）。
7. 文档全面改命令：`cargo run -p qidiwork-cli --bin bid_export -- …`；`docs/ops/{bid-export-cli,bid-project,bid-import,bid-packaging}.md` 同步。

### 3.3 验收标准

| # | 项 | 判据 |
|---|---|---|
| 1 | GUI 包只含 4 类文件 | 安装后目录 = `qidiwork-gui.exe` + `qidiwork.exe`(内核) + `templates\` + `uninstall.exe`；**无** `bid_*.exe` |
| 2 | NSI 无 "Copy external binaries" 段 | `grep -c "Copy external binaries" installer.nsi` == 0 |
| 3 | 库测试不退化 | `cargo test --lib office::bid` == 94 passed |
| 4 | CLI 可用 | `cargo run -p qidiwork-cli --bin bid_export -- --md …` → EXPORT OK；`bid_pages` 同 |
| 5 | CLI 安装态可解析模板 | 把 `qidiwork-cli` 产物与 `templates/` 放同目录 → `--check-only`/导出成功（`source=resource` 打印） |
| 6 | 前端不回归 | `npm run build` 通过 |
| 7 | 打包可复现 | 干净重建两次，安装包字节稳定（sha256 一致或仅时间戳差异） |

### 3.4 风险与缓解

| 风险 | 缓解 |
|---|---|
| `qidiwork-gui` 作为 bin+lib 被 CLI 依赖，可能触发 tauri 的 build 逻辑 | CLI 只依赖 lib target；`cargo build -p qidiwork-cli` 不会跑 `tauri_build` 的打包步骤（build.rs 只生成元数据） |
| 迁移后路径类测试依赖 `CARGO_MANIFEST_DIR` 指向变化 | 单测全在 lib 内，`CARGO_MANIFEST_DIR` 仍是 `gui/src-tauri`，不变 |
| 发布链要同时发 GUI 与 CLI 两个产物 | `prod/releases` 分开命名：`qidiwork-setup-x.y.z.exe` 与 `qidiwork-cli-x.y.z-win64.zip` |
| 迁移期双份代码 | 用 `git mv` 一次性移动，禁止复制；同 commit 内改完 |

### 3.5 回滚

单 commit 可回滚：`git revert <sha>` 即恢复 bin 在 GUI crate 内（安装包回到"多一个 bid_export.exe"的旧状态，不影响功能）。

### 3.6 工作量

约 1.5–2 小时（迁移 30 分钟 + 模板解析改造 30 分钟 + 文档/验收 30 分钟 + 一次干净打包 10 分钟）。

---

## 4. 不在本方案内

- 内核 `qidiwork.exe` 的版本校验（另立小项：打包前 `--version` 比对）；
- 代码签名；
- CLI 的独立安装包（先出 zip，签名后再做 installer）。
