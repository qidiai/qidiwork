# 方案：真实标书适配（标题/页数/图件）v2

**日期**：2026-11-18
**触发**：用 `Documents\QidiWork\投标方案-槐林镇…`（10 章 160 KB / 247 行表格）压测，暴露：
1. 源文件用 `# 一、工程概况`，而引擎要求 `#`=书名、`##`=章 → 直接喂入得 0 章；
2. 引擎对"一、"前缀不认识，输出成了 **"第一章 一、工程概况"**（重复编号）；
3. 实际 75 页，我按 50 页硬红线判定超限——**页数上限不该由我默认**。

---

## 0. 三条产品原则（本轮校正）

| # | 原则 | 含义 |
|---|---|---|
| P1 | **标题以"人怎么写"为准，不以 Markdown 为准** | 接受 `# 一、工程概况`、也接受纯文本 `一、工程概况`；输出永远是无 `#` 的真标题 |
| P2 | **页数上限来自外部约束，不内置默认** | 优先级：招标文件要求 > 用户显式指定 > **主动询问**；未指定就不卡 |
| P3 | **图件来自项目资料** | 平面图/效果图由用户提供（真实项目平面图），引擎只负责嵌入、缩放、图注；**不生成、不臆造** |

## 1. 标题与编号（修 P1 + 重复编号）

### 1.1 输入格式（项目模式，一章一文件）
按以下顺序识别"章标题"：
1. 文件第一行若是 Markdown 标题（`#`/`##`）→ 取文本；
2. 若是纯文本且匹配编号模式（`一、`/`（一）`/`第一章`/`1.`/`1  `）→ 视为章标题；
3. 都不匹配 → 用文件名（去 `NN-` 前缀）作章标题。

正文内：
- `###`/`####`（或纯文本 `1.1`/`1.1.1`）→ 节/子节；
- **不再按"H2 才是章"硬编码**；单文件 `--md` 模式保留旧语义（`#`=书名、`##`=章），避免破坏已有用户。

### 1.2 编号识别（防重复）
扩展"已编号"判定，命中任一即**不加前缀**：
- 中文序号：`^[一二三四五六七八九十百]+、`、`^（[一二三四五六七八九十]+）`；
- 中文章：`^第[一二三四五六七八九十百\d]+章`；
- 阿拉伯：`^\d+(\.\d+)*[.、\s]`。
> 现状只认"第…章"与"数字."，导致"一、"被当成未编号 → 加了"第一章"。

### 1.3 验收
- 输入 `# 一、工程概况` → 输出标题 **"一、工程概况"**（不得出现"第一章"）；
- 输入纯文本 `一、工程概况` → 同上；
- 输入 `# 工程概况`（无编号）→ 自动 `第一章 工程概况`（保持现行为）；
- 输出 docx 无 `#`、无 `##`（已有断言）。

## 2. 页数（修 P2）

### 2.1 上限来源
| 优先级 | 来源 | 实现 |
|---|---|---|
| 1 | 招标文件要求 | 由用户在导入/项目设置里录入（`bid.project.json` 增加 `max_pages`）；P1 从招标文件解析属后续 |
| 2 | 用户显式指定 | `--max-pages N`（已有）或 UI 输入 |
| 3 | 都没有 | **不设限**，导出后只报告实测页数；CLI 打印提示 `NO_PAGE_LIMIT（未指定上限，仅报告 pages=N）`；UI 在导出前询问"本项目页数上限？可留空" |

### 2.2 行为
- 指定上限且超限 → `PAGES_EXCEEDED pages=N max=M`，exit 3（已有），并给出"建议压缩档位"提示；
- 未指定 → `EXPORT OK pages=N`，不判定通过/失败。

### 2.3 验收
- `bid_project build` 无 `max_pages`/无 `--max-pages` → exit 0，输出 `pages=75`（本工程真实值）；
- 项目清单写 `"max_pages": 50` → 生效，exit 3；
- 两者都无且 UI 场景 → 弹窗询问（P1 前端）。

## 3. 图件（修 P3）

| 图类型 | 来源 | 引擎职责 |
|---|---|---|
| 平面图 / 效果图 / 现场照片 | **用户提供**（项目资料、图纸导出） | 按 `![](assets/xxx.png)` 嵌入、等比缩放、图注、`{ai}` 标注 |
| 横道图 | 可由 `gantt` 代码块原生生成 | 表格渲染（已实现） |
| 网络图 | 暂缓（P2 后续） | — |

**明确不做**：AI 生成平面图/效果图冒充项目图；不根据文字"推测"尺寸标注。
文档里要写明："平面图必须来自本项目图纸，缺图时导出前提示补图（warning，不阻断）"。

---

## 4. 压缩档位（仅在给定上限时启用）

超限时提供 `--compact`（或项目清单 `compact: true`）：
- 行距 1.5 → 1.2；页边距 1.2 → 1.6 cm；表格字号 12 → 9.5 pt；段后距 0；清理空段落。
- 输出压缩前后页数对比 `pages: 75 → 52`；仍超限则明确告知"需人工删减内容"，**不自动删内容**。
- 不得低于可读下限（正文 ≥ 10.5 pt）。

## 7. v3 修订（codely-core 审计 NO-GO，3 阻断 + 5 重要全部吸收）

> 本节优先于前文；冲突时以本节为准。

### 7.1 阻断 1：项目模式"首行"不可见 + 多 H2 契约未定义
- 根因：`project.rs:238-240 with_doc_title` 会预拼 `# {title}`，使文件自身 H1 变成"第二个 H1"被丢弃（`markdown.rs` 只取首个 H1）。
- 修正：
  1. 新增 `markdown::parse_chapter_markdown(src, base_dir, number)`：**先读真实首行**再决定章题，不再预拼书名；
  2. 契约（显式）：文件**以一个 H1 开头** → 该 H1 为章题，其余 `##`/`###` 为节/子节（一章一文件）；
     文件**不以 H1 开头** → 保持旧语义（每个 `##` 各自成章），兼容现有 skeleton 与 `build_merges_files_in_order`；
  3. `project.rs` 删除 `with_doc_title`，`build_request` 调 `parse_chapter_markdown`；skeleton 改为"一文件一章"模板，并同步该测试。

### 7.2 阻断 2：纯文本编号识别误伤正文
- 反例：`ch1.md:98` "29.32万平方米…"、`:106` "2.54万立方米…" 会命中 `^\d+[.、]` / `^\d+\.\d+`。
- 修正：**取消正文内的纯文本节号识别**（节/子节必须用 `###`/`####`）。
  章题纯文本识别只允许出现在**文件第一行**，且必须同时满足：行长 ≤ 40、无 `。；，`、匹配 `^([一二三四五六七八九十百]+、|（[一二三四五六七八九十]+）|第[一二三四五六七八九十百\d]+章|\d+[.、\s])`。
- 测试：以 ch1:98/106 原文作负例，断言不被当标题。

### 7.3 阻断 3：压缩档位自相矛盾
- 现状：`TableStyleCfg` 无字号字段；模板无 `w:after`；边距 1.2→1.6 是**增页**。
- 修正：
  1. `DocStyle` 新增 `table.size_pt: u32`（默认 12）与 `body.space_after_pt: u32`（默认 0），模板改为占位渲染；
  2. 压缩档位：行距 1.5→**1.3**、页边距 1.2→**1.0cm**、表字号 12→**10.5pt**（下限 10.5，不再提 9.5）；
  3. 删除"段后距 0"的空话，改为真实字段；
  4. 压缩后必须报告 `pages_before/pages_after`，仍超限则明确"需人工删减"，不自动删内容。

### 7.4 重要 1：缺图行为（硬错误 → 项目模式可降级）
- 现状：`markdown.rs:498-507` 是 `Err("图片不存在")`，与"绝不静默降级"一致。
- 修正（显式、可追溯）：
  - 单文件 `--md`：**保持硬错误**；
  - 项目模式：默认 `warn` —— 跳过该图、保留图注、写入 `problems`，并打印 `WARN 缺图: <path>`；提供 `--strict-images` 恢复硬错误。
  - docx 中**不得**留下悬空图片引用（跳过即不生成 drawing）。

### 7.5 重要 2：`max_pages` 优先级
- 规则：**CLI 显式 `--max-pages` 覆盖 manifest**；未给 CLI 才用 manifest；都没有则不设限。
- 记录来源：摘要输出 `"max_pages_source": "cli|manifest|none"`。

### 7.6 重要 3：页数测量时机与 token
- 仅在"有上限"或显式 `--pages` 时调用 WPS；否则不测、不报 pages（避免每次 build 10s+ 与 COM 失败路径）。
- 项目构建成功 token 是 **`BUILD OK`**（不是 EXPORT OK）；验收按实际 token 改写。

### 7.7 重要 4：真实表格列宽
- 现状等分 10546 twips，8 列表单列 ~1318 twips，158 字单元格必超高。
- 修正：按列内容长度加权（最小 12%、最大 45% 表宽，余量均分），并对"任一单元格 > 60 字"的行**关闭 `cantSplit`**，允许跨页。
- 验收：8 列表的首列/长文列宽度 > 等分值；长行不出现整行被推到下一页。

### 7.8 重要 5：补充可机判验收
1. 解包 out.docx：`document.xml` 含 `一、工程概况`，**不含** `第一章 一、`；
2. ch1:98/106 原文所在段无 `outlineLvl`；
3. 未指定上限：exit 0，摘要含 `"max_pages_source":"none"`，**不含 pages**；
4. manifest 50：`PAGES_EXCEEDED pages=75 max=50` exit 3；
5. `--compact`：输出 `pages_before/pages_after`，压缩后表格 `w:sz ≥ 21`（10.5pt）；
6. 19 张表：无单行超过一页（抽查最高行）。
