## A. GUI 账号功能（方案 P1-3 客户端部分）✅ 已实现

**Tauri 后端新模块 `gui/src-tauri/src/auth.rs`（新增，15KB）**，注册 3 个 IPC 命令（`lib.rs:60-62`）：

| 命令 | 功能 | 实现要点 |
|---|---|---|
| `auth_status` | 账号状态组装 | 本地读 `~/.qidi/auth.json`（scope key `{issuer}::{client_id}`）判登录态 → `GET {issuer}/v1/user` 在线拉取 email / user_id / 套餐 / 今日用量 / 配额 |
| `auth_login` | 设备码登录 | spawn 内核 `qidiwork login --device-auth` 子进程，逐行解析 stderr 提取设备码 + verification_uri，经 Tauri 事件推给前端 |
| `auth_logout` | 退出登录 | 清除本地登录态并返回刷新后的 AuthStatus |

**安全纪律（方案要求，已落实）**：
- access token 只在 Rust 侧持有（读 auth.json、发 /v1/user），**绝不下发前端**（auth.rs:6,83）
- 网络失败降级：`/v1/user` 不可用时仍以本地 token 判定 logged_in，前端暂显旧 email/user_id（auth.rs:8, 177-196）

**前端**：
- `gui/src/composables/useAuth.ts`（新增）：status / loading / loginPending / loginUri / loginCode / loginError / refresh / startLogin / logout
- `StatusBar.vue`（+15）：状态栏新增账号标签（`邮箱 · 套餐` 或"未登录"），点击打开设置面板
- `SettingsModal.vue`（+170）：设置面板新增"账号"区块——设备码登录引导（verification_uri 一键打开，经 opener 插件）、套餐徽章、今日用量与配额（zh-CN 千分位格式化）、手动刷新、退出登录
- 新增依赖：`reqwest 0.12`（`default-features=false` + `rustls-tls` + `json`，走系统信任链、不依赖系统 curl；Cargo.lock +300 行传递依赖全部 crates.io 官方源——审计确认供应链干净）

## B. 品牌迁移：xAI/Grok → QIDI/qidiai（客户端"换默认值"）✅ 已实现

- **OIDC 切换自建服务端**：`auth/config.rs:128` issuer `https://auth.x.ai` → `https://api.qidiai.ltd`；`:283` client_id UUID → `qidi-code`；`PROD_ACCOUNTS_APP_ORIGINS` 增补自建账号页（方案 §0 CORS 要求）
  ⚠️ 【破坏性变更】scope key 随之改变，旧登录态静默作废，升级后需重新登录（审计 MEDIUM，建议发布说明声明）
- **远程 API 域名**：`remote/*_client.rs`（chat/models/conversations/workspaces）全部指向 qidiai.ltd
- **推理/更新链自托管**：`cf-update/version.rs` CLI_BASE_URL 主/备均改 `https://qidiwork.qidiai.ltd/cli`（原 Cloudflare+GCS 双源，GCS 镜像暂缺→单源，审计 MEDIUM 技术债）
- **插件市场**：仓库 URL `xai-org/plugin-marketplace` → `qidiai/plugin-marketplace`（名称 `OFFICIAL_SOURCE_NAME` 仍为 "xAI Official"——审计 MEDIUM 待改）
