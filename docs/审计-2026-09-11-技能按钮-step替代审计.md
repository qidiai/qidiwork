## 审计方原始结论

总评:GO with fixes

Blocker:无

Warning:
1. useSkills.ts:15 — initSkills 失败后 loaded 永久为 true,导致后续无法重试技能列表加载(除非刷新页面)。建议:catch 块内重置 loaded=false,或暴露 retrySkills 方法。
2. WorkspaceSidebar.vue:34 — runSkill 未校验 currentTask.value 是否存在,若未选择工作区, prompt 将注入 "undefined" 字符串。建议:if (!currentTask.value) { pushSystem("请先选择任务工作区"); return; }
3. skills.rs:97 — list_skills 对 SKILL.md 无大小限制,恶意/损坏的极大文件可导致 OOM。建议:读取前检查 metadata(file_size),限制如 1MB,超限跳过。
4. skills.rs:78 — read_to_string 依赖系统默认编码,非 UTF-8 文件静默跳过,可能遗漏合法技能。建议:明确要求 UTF-8,或使用 read_to_string 的 error 分支记录日志。

Note:
1. skills.rs:46 — frontmatter 解析器仅剥离成对双引号,单引号值(如 description: 'hello')会保留引号显示。建议文档约定仅使用双引号,或扩展 strip_prefix/suffix 支持单引号。
2. WorkspaceSidebar.vue:25 — 办公技能过滤规则(office-*/bid-*)硬编码在前端,Rust 端返回全部技能。若前端逻辑被篡改(如恶意扩展、开发工具注入),可暴露非办公技能。建议:若技能含敏感信息,应在 Rust 端也按前缀过滤,或确保 ~/.qidi/skills 权限 700。
3. skills.rs:63 — 符号链接目录会被跟随读取 SKILL.md。攻击者若在 ~/.qidi/skills 创建指向 /etc/ 等敏感目录的符号链接,可能触发信息泄露(尽管 SKILL.md 缺失会跳过)。风险低(需本地写权限),但建议 read_dir 时过滤符号链接(entry.file_type()?.is_symlink())。
4. commands.rs:422 — skills_list 内使用同步 std::fs::IO,与 office_scan 同模式,已登记 W6。建议后续异步化(tauri::async_runtime::spawn_blocking)以避免阻塞线程池。
5. skills.rs:40 — 目录名通过 into_string() 转换,非 UTF-8 目录名被跳过。在 Unix 平台可能遗漏合法技能目录,建议使用 from_utf8_lossy 或记录警告。

结论一句话:功能实现符合方案 v2 P1 要求,无严重安全漏洞,但需修复前端重试机制、空任务校验及添加文件大小限制后即可合入。
