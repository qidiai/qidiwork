## k3 原始结论

总评:**GO with fixes**

Blocker:无

Warning:

1. `SettingsModal.vue` `save(true)`:未检查 `turnInProgress`,内核正在跑任务时「保存并重启内核」会 `agent_stop` 强杀进行中的 turn(前端无确认、无禁用)。建议:turn 进行中禁用该按钮或二次确认。

2. `settings.rs:115-119`(`[models]` 非表值覆盖为表):注释辩护成立(内核同样解析不出),但仍是"静默改写用户文件内容",违反本功能"绝不覆盖"纪律的精神。建议:与 `[model.*]` 缺失同样处理——拒绝并报错让用户手工修复。当前实现可接受,但需团队确认这是有意取舍。

3. 并发:`cf-pager/config_toml_edit.rs` 证实内核/TUI 也写同一 config.toml(`[hints]`),双方都是无锁读-改-写,存在丢失更新窗口(GUI 保存与内核 hints 落盘交错)。P2 最小实现可接受——窗口为毫秒级且两侧均 toml_edit 保格式——但应在代码注释或 worklog 中显式记录该已知竞态,后续若出现配置丢失投诉再引入文件锁。

Note:

1. 密钥卫生核实通过:前端链路只传 `has_api_key`;错误信息仅含 path/model_id,不含 key;tracing 日志未记录 command 参数;IPC 明文传参是 Tauri 标准做法。小改进:保存成功后 `apiKey.value = ""`,避免明文驻留 Vue ref。

2. `settings.rs:126`:`std::fs::write(&tmp, …)` 失败时不清理可能残留的半截 tmp 文件(仅 rename 失败路径清理了)。建议同样 `remove_file` 兜底。

3. `settings.rs` 读取:`model = { m1 = {…} }` 内联表或 dotted-key 定义的模型 `as_table()` 为 None,下拉框静默缺失;保存时不带 api_key 仍可将 default 指向它。GUI 路径不可达(选项来自读取列表),仅直接 IPC 可达,风险低,建议注释说明。

4. `SettingsModal.vue`:`saved` 置 true 后立即 `emit("close")`,「已保存。」提示永远不可见;死代码可删。

5. 状态机核实通过:`agent_stop` 杀进程 → `agent-exit` 事件 → `connected=false` → 下次 `sendTask` 走 `startSession` 重启新配置,闭环成立;`stopKernel` 失败时配置已保存、错误可见,语义一致。

6. 接线核实通过:`settings_read/settings_save` 已在 `lib.rs` 注册、`StatusBar.vue` 入口正常、`toml_edit 0.22` 与主工程同系;Windows 下 `fs::rename` 覆盖目标(`MOVEFILE_REPLACE_EXISTING`),原子写成立。

一句话结论:实现与声明的安全纪律相符、无密钥泄漏路径,可合入;合入前建议补上 turn 进行中禁止「保存并重启」的防护,并书面记录 config.toml 无锁竞态这一已知取舍。
