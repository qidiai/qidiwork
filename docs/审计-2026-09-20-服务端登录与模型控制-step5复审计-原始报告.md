### 发现清单（按严重级排序）

- [HIGH] gui/src-tauri/src/auth.rs:103-107 — `read_stored` 兜底逻辑可能在多账号场景下取错 token，导致将非当前 scope 的 access token 发送至 `/v1/user`，构成越权信息访问风险。
  证据：
  ```rust
  map.get(&scope_key()).cloned().or_else(|| {
      // 兜底:env 覆盖 issuer/client_id 与登录时不一致的老文件,取唯一非 API key 项。
      map.into_values()
          .find(|a| !a.key.trim().is_empty())
  })
  ```
  当 `auth.json` 中存在多个 scope（如个人账号 + 团队账号）且当前 scope 未命中时，该逻辑会按 BTreeMap 排序取第一个非空 key 的 token，而非当前配置 issuer/client_id 对应的 token。GUI 随后会用该 token 请求 `/v1/user`，可能返回错误账号的套餐/用量信息。
  建议：将兜底条件收紧为“仅当 map.len() == 1 时允许”，否则要求用户显式修正 `QIDI_OAUTH2_ISSUER`/`QIDI_OAUTH2_CLIENT_ID` 或返回未登录；避免静默取任意 token。
