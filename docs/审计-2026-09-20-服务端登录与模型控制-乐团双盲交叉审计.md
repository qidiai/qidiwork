## 指挥官仲裁后的合并发现清单

### [CRITICAL] 工作区 20 个乱码临时文件含真实明文 API Key，且每次测试运行持续再生成
- **位置/根因**：`crates/codegen/cf-pager/src/notifications/hooks.rs:104-110`（`sets_environment_variables`）与 `:137-140`（`omits_session_id_when_none`）把 Windows 临时路径未加引号拼进 shell 命令（`printf '...' > {}` / `env > {}`），经 `hooks.rs:14-16` 的 `Command::new("sh")`（Git Bash）执行时反斜杠被吃成转义符、盘符冒号被替换为全角"："，输出落到 CWD（仓库根与 cf-pager 目录）。
- **指挥官亲验**：4 个 7.4KB 文件为完整 `env` 转储，**含 6 个真实明文密钥**（MOONSHOT_API_KEY/OPENAI_API_KEY/DEEPSEEK_API_KEY/ZHIPU_API_KEY/ARK_API_KEY/AI_BRIDGE_TOKEN）；8 个 74-89B 为 printf 测试输出；4 个 0 字节 `.done`。文件名中的全角冒号在 NTFS 上真实存在（非显示层差异——T2 因无仓库访问权在此处误判）。
- **风险**：未跟踪但就在工作区，任何一次 `git add -A` 都会把密钥提交进历史；且 `cargo test -p cf-pager` 每次运行都会带最新环境重新生成。
- **T1 发现（CRITICAL）｜T2 降级误判（LOW）→ 仲裁：CRITICAL 成立**
- **修复**：① 立即删除 20 个文件 + cf-pager 目录下 4 个同类文件；② **轮换全部 6 个泄露密钥**；③ 修测试：改用 `std::fs::write` 落盘或路径 `replace('\\', "/")` 后加引号，或 `#[cfg(unix)]` 门控；④ `.gitignore` 增加对应模式兜底。

### [HIGH] 8 个 insta 快照孤儿化：crate 改名导致参考快照失配
- **位置/根因**：crate 已改名 `xai-grok-pager → cf-pager`（`cf-pager/Cargo.toml:2`），insta 参考文件名前缀应为 `cf_pager__`，但目录中只有 8 个旧前缀 `xai_grok_pager__scrollback__blocks__tool__edit__tests__*.snap`；测试运行只能生成 `.snap.new`，无参考可比对 → 这 8 个测试当前实际失败。
- **T1 发现并完成根因分析（HIGH）｜T2 仅列为残留（LOW）→ 仲裁：HIGH 成立**
- **修复**：`git mv` 旧前缀 → 新前缀（同步文件内 `source:` 路径），或 `cargo insta accept` 重录；`.gitignore` 加 `*.snap.new`。

### [MEDIUM] 合并项（4 项）
1. **GUI auth.rs 兜底逻辑可能取错 token**（`gui/src-tauri/src/auth.rs:103-107`）：scope key 未命中时静默取 BTreeMap 第一个非空 key 项，注释称"唯一"但代码不校验唯一性；多账号时会用错误 scope 的 token 请求 `/v1/user`。T2 判 HIGH（越权角度），T1 判 MEDIUM → **仲裁 MEDIUM**：服务端会拒绝跨 scope token，实际影响为显示错误账号信息/请求失败，非真正越权。修复：兜底收紧为 `map.len()==1` 时才允许，否则返回未登录。
2. **更新链失去异构回退源**（`cf-update/src/version.rs:18-26`、`install.sh:154`/`install.ps1:150`/`install-enterprise.*:154-158`）：fallback 与 primary 同为 `https://qidiwork.qidiai.ltd/cli`，单源宕机即全员更新失败。代码注释已声明系 GCS 镜像暂不可用的已知临时态 → 记录为技术债，建议恢复独立 fallback 或在错误提示中明确无回退。同时 `auto_update.rs:1194 download_verified_from_base` 需确认对下载物做哈希/签名强校验。
3. **品牌残留两处**（T2 独有，指挥官已验证）：`cf-plugin-marketplace/src/lib.rs:26 OFFICIAL_SOURCE_NAME = "xAI Official"`（连带 ~40 处测试断言需同步）；`cf-pager/src/app/cli.rs:299/305` 错误前缀 `qidi:` 应为 `qidiwork:`（与 `#[command(name="qidiwork")]` 及 main.rs 一致）。
4. **`build_release.ps1` UTF-8 无 BOM 在 PowerShell 5.1 下解析失败**（T1 独有，`build_console.txt` 有实锤：字符串缺少终止符错误）——加 BOM 或改用 pwsh 或文案 ASCII 化。（本次审计中指挥官的调度脚本因同样问题失败过一次，已实证。）

### [LOW] 合并项（6 项）
- 认证 scope key 变更（`auth/config.rs:128` issuer→`https://api.qidiai.ltd`、`:283` client_id→`qidi-code`）使旧安装 token 静默失效 → 需在发布说明中声明破坏性变更（T1）。
