## A. 项目工作区（bid_project）

### A.1 目录契约

```
<proj>/
  bid.project.json      # {"title":"…","style_id":null,"figure_width_cm":null,"chapters":["chapters/01-….md"]}
  chapters/01-概述.md
  chapters/02-….md
  assets/               # 图片
```

- `chapters` 为空或缺省 → 按 `chapters/*.md` **文件名升序**；显式列出则以列表顺序为准。
- 每个 md 文件按 `markdown::parse_markdown_with(src, chapter_file_dir, number)` 解析；**各文件自己的 H1 忽略**（书名取自 manifest），其 H2 各自成章。
- 章号连续：所有文件合并后再统一编号（用 `number` 参数控制）。

### A.2 `project.rs` API

```rust
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct ProjectManifest {
    pub title: String,
    #[serde(default)] pub style_id: Option<String>,
    #[serde(default)] pub figure_width_cm: Option<f32>,
    #[serde(default)] pub chapters: Vec<String>,
}

pub fn create_skeleton(dir: &Path, title: &str) -> BidResult<()>;   // 建目录 + manifest + 01-概述.md + assets/
pub fn load_manifest(dir: &Path) -> BidResult<ProjectManifest>;     // 读 bid.project.json
pub fn build_request(dir: &Path, number: bool) -> BidResult<BidExportRequest>; // 合并所有章节
pub fn validate_project(dir: &Path) -> BidResult<Vec<String>>;      // 返回问题列表（空=健康）
```

错误文案：`章节文件不存在: {p}` / `项目清单缺失: bid.project.json` / `章节目录为空: chapters/`。

### A.3 CLI `bid_project`

```bash
bid_project new <dir> --title "某县…施工组织设计"
bid_project build <dir> [-o out.docx] [--no-number]
bid_project check <dir>
```
- `build` 默认输出 `<dir>/out.docx`；成功后打印 JSON 摘要 + `BUILD OK`；校验失败 exit 1；参数/解析错误 exit 2。
- `check` 打印 `PROJECT OK` / `PROJECT FAIL <问题,逗号分隔>`。
- `new` 已存在 manifest → `ERROR 项目已存在` exit 2。

### A.4 测试（5 个，写在 project.rs 测试模块）
1. `skeleton_created`：new 后三个路径存在，manifest 可读回
2. `build_merges_files_in_order`：两文件各 1 章 → 2 章，顺序按文件名
3. `missing_chapter_reported`：manifest 列了不存在文件 → Err 含 `章节文件不存在`
4. `empty_chapters_rejected`：chapters 目录空 → Err 含 `章节目录为空`
5. `validate_reports_missing_image`：md 引用不存在图片 → `validate_project` 返回 1 条问题

## C. DOCX 导入（bid_import）

### C.1 API（`import_docx.rs`）

```rust
pub struct ImportStats { pub chapters: usize, pub headings: usize, pub paragraphs: usize, pub tables: usize, pub images: usize }

/// 读 docx → Markdown 文本；图片抽到 assets_dir，md 中写 assets/<name>
pub fn import_docx(docx: &Path, assets_dir: &Path) -> BidResult<(String, ImportStats)>;
```

### C.2 映射规则
- `w:pStyle`：
  - `BidTitle1`：**首个** → `# `（书名）；后续 → `## `（章）
  - `BidTitle2` / `BidTitle3` / `BidTitle4` → `###` / `####` / `#####`
  - 内置 Word 样式：`1`/`Heading1` → 同上 H1/H2 逻辑（首个 H1 为书名）；`2`/`Heading2` → `##`；`3` → `###`
  - `BidCaption` → 若上一块是图片，则作为该图片的图注 `![图注](…)`；否则普通段落
- 普通段落（`BidBody` 或无样式）→ 段落文本（拼接 run 文本，trim；空段落丢弃）
- `<w:tbl>` → GFM 表格（首行表头；无边框也照转）
- `<w:drawing>` → 从 `word/media/` 抽对应图片到 `assets_dir`（文件名 `img-<n>.<ext>`），md 中 `![](assets/img-n.png)`
- 跳过：页眉页脚、TOC 域结果、`w:sdt` 包装（只管里面内容）

### C.3 CLI `bid_import`

```bash
bid_import --input old.docx --out new.md [--assets <dir>]
```
- `--assets` 缺省 = `new.md` 同目录的 `assets/`（自动创建）
- 成功：JSON 摘要 + `IMPORT OK`；失败 `ERROR <原因>` exit 2。

### C.4 测试（4 个）
1. `imports_our_export`：用 `gui/tests/bid-export/out/md-demo.docx` → 章节/图/表计数与导出时一致（chapters≥3、images=5、tables≥1）
2. `builtin_heading_styles_mapped`：用 `DocxPackage` 造一个 `<w:pStyle w:val="1"/>` 的 docx → 首个变 `#`
3. `table_to_gfm`：合成 2×2 表 → md 含 `| a | b |`
4. `missing_file_error`：不存在路径 → Err
