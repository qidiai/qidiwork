**校验规则（`BidExportRequest::validate()`，T1 写）**：
- `title` trim 后非空；`chapters` 非空（空报错 `"至少需要一章"`）。
- `output_path` 由命令层/fixture 注入后校验非空（`validate()` 允许空，`export()` 在写盘前报 `"输出路径为空"`）。
- 每章 `title` 非空；`blocks` 允许为空。
- `Table`：`header` 非空；每行 `cells.len() == header.len()`，否则报 `"表格第 N 行列数不符"`。
- `Figure`：`path` 非空（文件存在性在 fill 阶段报错）。
- 错误类型统一 `BidError`（见 §4.1）。

## 4. 底座（`docx.rs`，T1 交付）

### 4.1 错误类型（T1 放 `mod.rs`）

```rust
#[derive(Debug)]
pub struct BidError(pub String);
impl BidError { pub fn new(s: impl Into<String>) -> Self { Self(s.into()) } }
impl std::fmt::Display for BidError { /* 输出内层 */ }
impl std::error::Error for BidError {}
impl From<std::io::Error> for BidError { /* 包一层文案 */ }
pub type BidResult<T> = Result<T, BidError>;
```

### 4.2 API

```rust
/// docx = zip 包；entries 全量读入内存（模板 <50KB，样本导出 <2MB，可接受）
pub struct DocxPackage { pub entries: std::collections::BTreeMap<String, Vec<u8>> }

impl DocxPackage {
    pub fn open(path: &std::path::Path) -> BidResult<Self>;
    /// 写 zip；`[Content_Types].xml` 必须第一个条目
    pub fn save(&self, path: &std::path::Path) -> BidResult<()>;
    pub fn text(&self, name: &str) -> BidResult<String>;           // UTF-8 严格解码
    pub fn set_text(&mut self, name: &str, xml: String);
    pub fn contains(&self, name: &str) -> bool;
    /// 写 word/media/<stem>-<n>.png + 补 rels + 补 [Content_Types]；返回 rId（形如 "rId5"）
    pub fn add_png(&mut self, bytes: &[u8], stem: &str) -> BidResult<String>;
}

/// 1cm = 360000 EMU
pub fn emu_from_cm(cm: f32) -> u64;
/// 用 image crate 读像素尺寸（只支持 png/jpeg）
pub fn image_size_px(path: &std::path::Path) -> BidResult<(u32, u32)>;
/// 生成 <w:r><w:drawing>…</w:drawing></w:r>（见 §6.3）
pub fn drawing_run(rid: &str, cx: u64, cy: u64, doc_pr_id: u32, caption: &str) -> String;
/// XML 文本转义：& < > " '
pub fn escape_xml(s: &str) -> String;
```

**zip 依赖写法（T1 直接照抄）**：

```toml
zip = { version = "3", default-features = false, features = ["deflate"] }
quick-xml = "0.42"
image = { version = "0.25", default-features = false, features = ["png", "jpeg"] }
```

**`add_png` 细节（必须照做，验收会查）**：
1. 媒体名 `word/media/<stem>-<n>.png`，`<n>` 从 1 起，冲突递增。
2. `word/_rels/document.xml.rels` 在 `</Relationships>` 前插入：
   `<Relationship Id="rId{N}" Type="http://schemas.openxmlformats.org/officeDocument/2006/relationships/image" Target="media/<stem>-<n>.png"/>`
   `N` = 现有 `rId` 数字最大值 +1。
   **兜底**：若找不到 `</Relationships>`（自闭合写法），把根元素的结尾 `/>` 改写成 `>…</Relationships>` 再插——否则含图导出必失败。
3. `[Content_Types].xml` 若无 `Extension="png"`：**插到第一个 `<Override` 之前；无 Override 则插到 `</Types>` 前**（`Default` 必须排在所有 `Override` 之前）：
   `<Default Extension="png" ContentType="image/png"/>`

### 4.3 单元测试（T1 必须写，`cargo test --lib office::bid` 可见）

1. `escape_xml`：`a<b&c>"d'` → `a&lt;b&amp;c&gt;&quot;d&apos;`。
2. `emu_from_cm(1.0) == 360000`；`emu_from_cm(15.5) == 5580000`。
3. `image_size_px(../tests/bid-export/assets/image3.png) == (840, 289)`（路径用 `env!("CARGO_MANIFEST_DIR")` 拼）。
4. `DocxPackage` round-trip：open 模板 → save 到临时目录 → 再 open → `text("word/document.xml")` 相等。
5. `add_png`：加入后 `contains("word/media/x-1.png")`，rels 含新 rId，content-types 含 `Extension="png"`。

**测试内允许 `unwrap`**：测试模块头加 `#![allow(clippy::unwrap_used, clippy::expect_used, clippy::panic)]`。

## 6. 填充器（T2 交付）

### 6.1 `template.rs`：sdt 索引与替换

```rust
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct SdtRange {
    pub tag: String,
    pub block_start: usize,   // "<w:sdt" 起始字节
    pub block_end: usize,     // "</w:sdt>" 结束后字节（含）
    pub content_start: usize, // <w:sdtContent> 结束 ">" 之后
    pub content_end: usize,   // </w:sdtContent> 起始 "<" 之前
}

pub fn index_sdt(xml: &str) -> BidResult<Vec<SdtRange>>;
pub fn find<'a>(ranges: &'a [SdtRange], tag: &str) -> Option<&'a SdtRange>;
pub fn content<'a>(xml: &'a str, r: &SdtRange) -> &'a str;
pub fn block<'a>(xml: &'a str, r: &SdtRange) -> &'a str;
/// 应用若干替换（按 start 降序处理，避免偏移漂移）
pub fn apply_edits(xml: &str, edits: &mut Vec<(usize, usize, String)>) -> String;
```

**实现要点（唯一可行解，别自创）**：
- `quick_xml::Reader::from_str(xml)`；每轮进循环前记 `let prev = reader.buffer_position() as usize;`，事件返回后 `let cur = reader.buffer_position() as usize;` → 本事件原文正是 `&xml[prev..cur]`（Text 事件亦然）。
- 维护栈 `Vec<Frame>`，`Frame { tag: Option<String>, content_start: Option<usize>, block_start: usize }`。
  - `Event::Start` 且名字 `w:sdt` → push（`block_start = prev`）；
  - **`Event::Empty` 且名字 `w:tag`（本模板全部 `<w:tag …/>` 都是自闭合，走 Empty 不走 Start）→ 从属性取 `w:val`，写入栈顶 `tag`；同时保留 `Event::Start` 分支兜底**；
  - `Event::Start` 且名字 `w:sdtContent` → 栈顶 `content_start = Some(cur)`；
  - `Event::End` 且名字 `w:sdtContent` → 记 `content_end = prev`（暂存栈顶）；
  - `Event::End` 且名字 `w:sdt` → pop，若 `tag` 与 `content_start/content_end` 齐全则 push `SdtRange { block_end: cur, .. }`。
  - `Event::Empty` 且名字 `w:sdt`（理论不出现）→ 忽略。
- 属性名比较用 `attr.key.as_ref()`（`quick_xml::name::QName`）与 `b"w:val"` 比较；命名空间前缀恒为 `w:`（模板由我们生成）。
- **禁止**：字符串 `find("<w:sdt")` + 手写深度计数（嵌套会错）；必须走事件流。

**单元测试（必须）**：
1. 对 `template_gen::template_document_xml()` 建索引 → 恰好 9 条，tag 集合 == `ALL_TAGS` 集合。
2. 全部 `content_start <= content_end`、`block_start < content_start`、`content_end < block_end`，且 `&xml[block_start..block_start+6] == "<w:sdt"`、`&xml[content_end..content_end+15] == "</w:sdtContent>"`（`</w:sdtContent>` 共 **15** 字节）。
3. 嵌套正确：`BID_CHAPTER` 的内容含 `BID_CHAPTER_TITLE` 与 `BID_CHAPTER_BODY`；`BID_CHAPTERS` 含 `BID_CHAPTER`。
4. `apply_edits` 两处编辑（前面的先改、偏移是否漂移）结果符合预期（自造小样本字符串）。
5. 不含 sdt 的 XML → 索引返回空 vec，不 panic。

### 6.2 `fill.rs`

```rust
pub fn export(req: &BidExportRequest, template: &std::path::Path, out: &std::path::Path) -> BidResult<(FillStats, u64)>;
```

流程（严格按序）：

1. `req.validate()?`。
2. `DocxPackage::open(template)`；取 `word/document.xml` 为 `xml`。
3. `index_sdt(&xml)?`；对 `ALL_TAGS` 逐个 `find`，任一缺失 → `BidError("模板缺少锚点 {tag}")`。
4. **部件取用（从原串切片）**：
   - `chapter_tpl = content(&xml, BID_CHAPTER)`（整段章模板字符串，**唯一需要取用的部件**）
   - 表格/图片/图注的渲染一律走 §5.5 片段库（`BID_TABLE_ROWS`/`BID_FIGURE_SINGLE` 只被删除、不被取用）
5. **章渲染**：对 `chapter_tpl` 再 `index_sdt` → `BID_CHAPTER_TITLE` / `BID_CHAPTER_BODY` 必须存在；逐章：
   - 标题（**必须保留 `<w:pageBreakBefore/>`**）：
     `<w:p><w:pPr><w:pStyle w:val="BidTitle1"/><w:pageBreakBefore/></w:pPr><w:r><w:t xml:space="preserve">{escaped}</w:t></w:r></w:p>`
   - 正文：按 `blocks` 顺序生成（§6.4），拼成 `body_xml`；**`blocks` 为空时 `body_xml` 为空串**（不要塞占位段落，否则 `BidBody` 计数会多）
   - 在章模板副本上用 `apply_edits` 替换 title/body 内容 → `chapter_out`
6. **文档装配**：edits =
   - `(doc_title.content_start, content_end, 标题段)`；标题段 pStyle 固定 `BidTitle1`（与章标题同款，故 `BidTitle1` 总数 = 章数 + 1）
   - `(chapters.content_start, content_end, 所有 chapter_out 拼接)`
   - `(table_rows.block_start, block_end, "")`（整块删除）
   - `(figure_single.block_start, block_end, "")`（整块删除）
   然后 `apply_edits(&xml, &mut edits)` → 新 `document.xml`
7. `set_text("word/document.xml", new_xml)`；`save(out)`；返回 `(stats, bytes)`。
8. 父目录不存在先 `create_dir_all`。

**图片**：每张图各自 `add_png`（`stem` = `fig-<n>`，n 全局从 1 递增），rId 用返回值；`doc_pr_id` 从 1 递增。

### 6.3 单图 XML（`docx.rs::drawing_run` 生成）

```xml

尺寸算法（**照做**）：
- `width_em = emu_from_cm(req.figure_width_cm.unwrap_or(15.5))`（15.5cm = 5,580,000 EMU）
- `height_em = width_em * px_h / px_w`（整数运算，四舍五入）
- 若 `height_em > emu_from_cm(20.0)` → `width_em = emu_from_cm(20.0) * px_w / px_h`，保持比例
- P0a 恒"每图一注"：`ai_generated=true` 时图注 = `caption + "（AI 生成示意图）"`，否则 = `caption`

/// 解析模板真身。dev: CARGO_MANIFEST_DIR/resources/templates/；安装态: resource_dir()/templates/
pub fn resolve_template_path(app: &tauri::AppHandle, style_id: &str) -> Result<std::path::PathBuf, String>;
pub const DEFAULT_STYLE_ID: &str = "bid-engineering-blue-v1";
```

规则：
1. `style_id` 只允许 `[a-z0-9-]`，否则 `Err("非法的模板 id")`（**路径穿越防护，必须做**）。
2. 候选 1：`app.path().resource_dir()?.join("templates").join(format!("{style_id}.docx"))`
3. 候选 2：`PathBuf::from(env!("CARGO_MANIFEST_DIR")).join("resources/templates").join(...)`
4. 存在即返回；都不存在 `Err("模板未找到: {name}")`。
