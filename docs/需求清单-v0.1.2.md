## R1【高】更新通知链路补全（v0.1.1 复盘发现的产品缺口）

**问题**：v0.1.1 已上线但存量 v0.1.0 用户**收不到任何更新通知**。
根因四断点：latest.json 客户端不消费（仅官网显示）；内核版本号未变（0.1.220-alpha.4 两版相同）；三个版本源（npm / GitHub Release / 自托管 /cli）都没发布内容；GUI 无更新感知（无 plugin-updater）。

**需求**：
1. 内核版本号 bump：cf-pager-bin / cf-update `0.1.220-alpha.4 → 0.1.220-alpha.5`（通知机制的比对锚点）
2. 自托管版本清单部署到 `qidiwork.qidiai.ltd/cli/`（格式对齐 `cf-update/src/version.rs` 的 fetch_gcs_version 解析逻辑；发布动作，归发布流程）
3. GitHub Release 补建（`gh release create v0.1.1` 起步，后续随版发布）——次源兼开源门面
4. GUI 新版本提示条：启动时拉 `/releases/latest.json`（nginx 已配 no-cache + CORS *），`latest.gui.version > 自身` 时设置面板/状态栏显示「新版本可用 → 打开官网下载页」。**不做自动升级**（NSIS 覆盖安装即升级）
5. NSIS 覆盖安装验证：v0.1.1 存量机直接跑 v0.1.2 setup，确认覆盖不并存

**DoD**：v0.1.1 机器（改 hosts 模拟）启动 GUI 30 秒内出现更新提示；内核 `check_update_status` 能从 /cli 源拿到 alpha.5 并提示升级。

## R2【高】错误日志一键导出（用户支持通道最后一公里）

**问题**：日志记录三层齐全（GUI tracing 日志 / 内核 unified.jsonl / 崩溃恢复会话），但用户**没有任何途径把日志交给开发者**——需手动找两个隐藏目录打包，普通用户不可行。

**需求**：
1. 设置面板新增「📋 导出诊断日志」按钮，一键打包到**桌面** `qidiwork-diag-<日期>-<时间>.zip` 并自动打开所在文件夹：
   - GUI 日志（app_log_dir 当天+前一天）
   - 内核 unified.jsonl **最近 2000 行**（防全量大文件）
   - 版本信息（GUI 版本/内核版本/OS 版本）+ auth 登录态（仅 yes/no，不导 token）
2. **隐私红线**：导出前自动扫描并掩码 `sk-[A-Za-z0-9]{16,}` / token 字段（复用内核 redact 逻辑思路）；zip 内附 README 告知脱敏范围
3. 内核侧（可后置 v0.1.3）：`qidiwork doctor` 诊断命令（检查 API Key 有效性/auth.json/网络/磁盘权限，输出可复制文本）

**DoD**：dev 模式点按钮 → 桌面出现 zip → 解开含三类内容且无明文密钥（人工抽检）。
